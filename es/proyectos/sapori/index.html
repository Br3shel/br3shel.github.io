EXPERIMENT / 004

SAPORI.

Desarrollo individual de una plataforma para restaurantes que combina administración de menús, acceso por QR y visualización de platillos en 3D y realidad aumentada.

TIPO

Aplicación full stack

TECNOLOGÍAS

React / Django / model-viewer / Django Channels / Tailwind CSS / GitHub

MI PARTICIPACIÓN

Desarrollo individual de frontend y backend

LABORATORIO DIGITAL

Proyecto individual · Menús digitales en tres dimensiones.

ReactDjangomodel-viewerDjango ChannelsTailwind CSSGitHub

01 — La idea

SAPORI propone que la consulta de un menú vaya más allá de una lista de nombres y precios. Un comensal puede explorar platillos, revisar sus detalles y abrir un modelo tridimensional desde el navegador.

La plataforma separa esa experiencia pública de las herramientas con las que un restaurante administra su oferta, sus enlaces QR y su información.

02 — Mi participación

Desarrollé el proyecto por mi cuenta, trabajando tanto en el frontend con React como en el backend con Django. Mi aportación comprende la aplicación web y la integración de sus funcionalidades.

Integré el visor de modelos 3D asociados a los platillos con la experiencia de consulta del menú.

Utilicé Git y GitHub para el control de versiones y el seguimiento de los cambios durante el desarrollo individual.

03 — La plataforma

  • Menú público por restaurante, con categorías, disponibilidad y detalles de los platillos.
  • Filtros por precio, alérgenos y recomendaciones del chef.
  • Visor 3D integrado con model-viewer, con soporte para realidad aumentada en dispositivos compatibles.
  • Panel para gestionar menús, categorías, archivos multimedia y puntos de acceso QR.
  • Separación entre administración de restaurantes y administración general de la plataforma.
  • Módulos de soporte y notificaciones con Django Channels.

React y Tailwind CSS componen la interfaz. Django REST Framework organiza la API; Django Channels permite los canales de comunicación en tiempo real.

04 — La experiencia en tres dimensiones

Los platillos pueden tener una imagen, un modelo 3D y otros archivos asociados. El visor permite abrir el modelo, girarlo y acercarlo antes de continuar explorando el menú.

Captura de la ejecución local con datos de demostración. La vista 3D se comprobó en escritorio; la proyección sobre una mesa mediante la cámara requiere un móvil compatible y no forma parte de esta verificación.

05 — Ejecución y validación

Para revisar el proyecto se ejecutaron el frontend y la API con una base temporal y registros ficticios, separados de la información original. Se comprobaron el inicio de sesión con una cuenta de demostración, el panel del restaurante, la carga del menú público y la apertura de un modelo 3D servido por Django.

Las imágenes muestran esa revisión local. Los nombres, precios y datos de demostración no representan métricas de uso ni información operativa de restaurantes reales.

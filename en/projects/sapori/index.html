EXPERIMENT / 004

SAPORI.

Solo development of a restaurant platform combining menu management, QR access, and dish visualization in 3D and augmented reality.

TYPE

Full-stack application

TECHNOLOGIES

React / Django / model-viewer / Django Channels / Tailwind CSS / GitHub

MY PARTICIPATION

Solo frontend and backend development

DIGITAL LABORATORY

Solo project · Digital menus in three dimensions.

ReactDjangomodel-viewerDjango ChannelsTailwind CSSGitHub

01 — The idea

SAPORI proposes taking menu browsing beyond a list of names and prices. Diners can explore dishes, inspect their details, and open a three-dimensional model in the browser.

The platform separates this public experience from the tools restaurants use to manage their offerings, QR links, and information.

02 — My participation

I developed the project on my own, working on both the React frontend and the Django backend. My contribution covers the web application and the integration of its features.

I integrated the viewer for dish-associated 3D models with the menu browsing experience.

I used Git and GitHub for version control and tracking changes throughout solo development.

03 — The platform

  • Public menus per restaurant with categories, availability, and dish details.
  • Filters for price, allergens, and chef recommendations.
  • An integrated model-viewer 3D viewer, with augmented reality support on compatible devices.
  • A panel for managing menus, categories, media files, and QR entry points.
  • Separate restaurant and platform administration roles.
  • Support and notification modules built with Django Channels.

React and Tailwind CSS form the interface. Django REST Framework organizes the API, while Django Channels provides real-time communication channels.

04 — The three-dimensional experience

Dishes can have an image, a 3D model, and other associated files. The viewer lets diners open, rotate, and zoom into a model before continuing to browse the menu.

Screenshot from a local execution with demonstration data. The 3D view was checked on desktop; placing a dish on a table through the camera requires a compatible mobile device and was outside this verification.

05 — Execution and validation

The frontend and API were run with a temporary database and fictional records, separate from the original information. Login with a demonstration account, the restaurant dashboard, the public menu, and the opening of a 3D model served by Django were verified.

The images document this local review. Demonstration names, prices, and data do not represent usage metrics or operational information from real restaurants.
